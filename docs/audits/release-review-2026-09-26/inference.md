# Pre-release review: larql-inference, larql-router, larql-router-protocol

Scope sizes: larql-inference/src = 81.5k lines (≈10.5k of it test files living in src/), larql-router/src ≈ 3.8k, larql-router-protocol/src ≈ 0.5k. Read-only review; nothing modified.

Severity: P0 = release blocker, P1 = fix before release, P2 = debt / follow-up.

No P0 found.

## 4. Hardcoding to a module/backend

Overall this area is good. Metal is reached only through the three factories in `src/lib.rs:108,135,156` (`#[cfg(all(feature="gpu", target_os="macos"))]`), and fused-path selection is capability-based (`layer_graph/generate/cpu.rs:23` `backend.supports(Capability::PrefillQ4|DecodeToken)`). There are no downcasts to `MetalBackend` in production code.

| Sev | Location | Finding | Fix |
|---|---|---|---|
| P1 | `layer_graph/generate/gpu/mod.rs:254-258` | `LARQL_METAL_PLE` env var decides whether per-layer-embedding models use the fused path. Without the variable, the code **silently** falls back to CPU (`:259-270`). This is a Metal-named env switch in generic generate logic. | Add `Capability::PerLayerEmbeddings` to the backend trait. When it is absent, surface the fallback in `GenerateResult` (which path ran), not via env. |
| P1 | `residual_diff/capture.rs:410-425`, `residual_diff/stages.rs:483-513` | Stage capture works by **process-global `std::env::set_var`** of the dump-dir variable that the backend reads. That is a backend coupling through an env side-channel. `set_var` from a library while other threads read env (e.g. the `forward_overrides` registry, `decode_stages.rs:19`) is unsound, and it is `unsafe` in edition 2024. The mutex only serialises callers of this fn. | Pass a dump sink or dir through the backend API (a `DumpHook` on the capture call) instead of env mutation. |
| P2 | `vindex/kquant_forward/generation.rs:230` | `LARQL_DIRECT_DECODE_STEP` env selects the decode algorithm inside a library function, and the choice is not recorded in the output. | Move it to an explicit option on the call or policy struct. Record the chosen path. |
| P2 | `vindex/kquant_forward/generation.rs:234` | `larql_compute::default_backend()` is constructed inside a generate fn, so the caller cannot inject a backend. | Take `&dyn ComputeBackend` as a parameter. |
